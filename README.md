# 答題擂台(GitHub 版．Firebase 同步)

這是「答題擂台」的免登入版本,讓**沒有 Claude 帳號的同事也能參加**。上傳到 GitHub(搭配 GitHub Pages)就能直接使用,不需要申請任何新帳號——因為你已經有一個 Firebase 專案(`kahoot-ns`),這個版本的即時同步就是用它來做的。

## 這個版本跟原本的差異

- **不需要登入 Claude。** 原本的版本靠 Claude 平台的帳號系統即時同步資料,這個版本改用 **Firebase Realtime Database**——你自己 Firebase 專案裡的即時資料庫,主持人跟參與者只要知道同一組「房間代碼」就能同步,任何人用瀏覽器打開連結就能玩,不用登入任何帳號。
- **主持人跟參與者是兩個完全獨立的網頁**:`host.html`(主持人用)跟 `index.html`(參與者用),畫面、操作邏輯都分開。
- **題目本身不會經過網路傳輸**:兩個頁面都載入同一份本機的 `quiz-data.js`,網路上只會同步「目前進行到第幾題、剩多少秒、誰答對、分數多少」這類即時狀態,不會傳送題目內容本身。
- 計分方式、答題玩法跟原本完全一樣。
- **遊戲結束後會自動清理資料庫**:主持人按下「結束遊戲」時,程式會把這個房間在 Firebase 裡留下的資料刪掉,避免資料庫裡房間代碼越積越多。如果中途不小心關掉瀏覽器、沒有按到「結束遊戲」,那個房間的資料會留在資料庫裡——這只佔用一點點免費額度內的儲存空間,不影響功能,之後要清也可以直接到 Firebase 主控台手動刪除。

## 檔案說明

上傳到 GitHub 的只需要這 5 個檔案:

| 檔案 | 用途 |
|---|---|
| `index.html` | 參與者畫面(加入遊戲、答題) |
| `host.html` | 主持人畫面(開始遊戲、公布答案、看排行榜) |
| `quiz-data.js` | 題庫內容,想改題目就改這個檔案 |
| `common.js` | 共用邏輯(計分、Firebase 即時同步、畫面小工具)——你的 Firebase 專案設定值也寫在這個檔案裡 |
| `style.css` | 樣式 |

(這個資料夾裡如果還有 `test-sim.js`、`node_modules/`之類的檔案,那些只是我開發時用來自動測試的工具,**不需要上傳**,可以刪掉或不理它們。)

## Firebase 這邊要確認的事(這部分我已經幫你弄好了)

這個版本接的是你的 Firebase 專案 **kahoot-ns**,底下已經開通 Realtime Database(位置:美國 us-central1)。`common.js` 裡已經寫好對應的設定值,不用再手動填。

**唯一要麻煩你確認/調整的是資料庫的「規則」**,因為目前你開的是測試模式,會在 **2026-11-27 之後自動鎖住、所有人都讀寫不了**。要長期使用,請到 Firebase 主控台 →「Realtime Database」→「規則」分頁,把內容換成:

```json
{
  "rules": {
    "quizArena": {
      "rooms": {
        "$code": {
          ".read": true,
          ".write": true
        }
      }
    }
  }
}
```

這組規則的意思是:只開放 `quizArena/rooms/房間代碼` 這個路徑底下可以自由讀寫(因為同事不會登入任何帳號,所以只能靠「知道房間代碼」當作存取門檻,概念上跟原本 ntfy.sh 版本是一樣的道理),資料庫裡其他路徑則維持預設的禁止存取。貼上後按「發佈」就會立刻生效,而且不會再有到期日的問題。

(如果你的 Firebase apiKey 看起來像密碼一樣,不用擔心——Firebase 的 `apiKey` 本來就是設計成會寫在瀏覽器端程式碼裡的公開值,真正的存取控制是靠上面這組「規則」,不是靠隱藏 apiKey。)

## 怎麼部署到 GitHub Pages

1. 在 GitHub 建一個新的 repository(public 或 private 都可以,但 private repo 的 Pages 功能依你的 GitHub 方案而定,建議用 public)。
2. 把上面那 5 個檔案上傳到這個 repository 的根目錄(直接拖拉上傳,或用 git push 都可以)。
3. 進入 repository 的 **Settings → Pages**,Source 選擇 `main`(或你的預設分支)的根目錄,儲存。
4. 等一兩分鐘,GitHub 會給你一個網址,類似:
   `https://你的帳號.github.io/你的repo名稱/`

## 怎麼使用

部署好之後,你會有兩個連結:

- **參與者連結**(傳給所有同事):`https://你的帳號.github.io/你的repo名稱/index.html`(或 `.../你的repo名稱/`,大部分情況會自動抓到 index.html)
- **主持人連結**(只有你自己用):`https://你的帳號.github.io/你的repo名稱/host.html`

兩個連結本身就是分開的網址,不需要額外的密鑰參數。

流程:
1. 你(主持人)打開 `host.html`,點「開始遊戲」,畫面會顯示一組 6 位數房間代碼。
2. 把這組代碼告訴參與者,他們打開 `index.html`,輸入代碼跟暱稱即可加入等候室。
3. 你確認人到齊後按下一步,就會開始出題。
4. 玩完之後記得按「結束遊戲」,讓這個房間的資料從資料庫清掉。

## 怎麼計分

答對的分數會依「答題速度」而定,越快答對分數越高(介於 500~1000 分之間的一個比例),答錯則是 0 分。每一題有自己的作答時限(在 `quiz-data.js` 裡設定),超過時限送出會被擋下。

## 怎麼改題目

打開 `quiz-data.js`,裡面是一個 JavaScript 陣列,每一題(或每個關卡公告)都是一個物件,格式大致如下:

```js
{
  type: "question",
  title: "關卡名稱",
  text: "題目文字",
  options: ["選項A", "選項B", "選項C", "選項D"],
  correctIndex: 1,          // 正確答案是第幾個選項(從 0 開始算)
  duration: 20,              // 作答時間(秒)
  explanation: "答案小知識說明"
}
```

改完存檔、重新上傳到 GitHub(或直接在 GitHub 網頁上編輯該檔案並 commit),GitHub Pages 會在幾十秒到幾分鐘內自動更新。

## 其他需要注意的小地方

- **Firebase 免費額度**:Realtime Database 的免費額度(Spark 方案)對這種偶爾辦一場、十幾二十人參加的活動來說綽綽有餘,不太需要擔心費用問題。如果以後要給很多場活動、很多人同時用,再留意一下主控台的用量頁面即可。
- **公司網路可能會擋**:有些公司或公用 Wi-Fi 會擋掉不常見的網域,建議正式使用前,先在實際會用到的網路環境(比如公司 Wi-Fi)測試一次能不能正常連上 Firebase、順利同步。
- 主持人畫面重新整理瀏覽器也沒關係,只要是**同一台裝置、同一個分頁**,會自動跳出「要不要接續剛剛未完成的遊戲」的提示;但如果是換一台電腦開主持人畫面,就會變成全新的遊戲。
